# 학술제 발표 구성안 (페이지별로 넣을 것)

PPT를 직접 만들 때 쓰는 자료입니다. 페이지마다 **제목(한 줄 메시지)**, **넣을 것**, **말할 것**, **근거 파일**을 적었습니다. 숫자는 모두 근거 파일에서 확인할 수 있습니다. 발표 10~12분, 19쪽 기준입니다.

## 발표 전체의 한 문장

> **오늘 내가 쓴 말이 내 단어장이 되는 영어 기록 앱**
> 모으고(기록) → 지키고(데이터 안전) → 다시 꺼내 보게(복습) 합니다.

첫 쪽과 마지막 쪽에 같은 문장을 넣고, 중간의 모든 기능은 이 문장을 뒷받침하는 이유로 설명합니다. 친구 원본의 문장 "작은 기록이 모여 나만의 언어가 돼요"를 부제로 함께 쓰면 출발점과도 이어집니다.

## 1부. 왜 만들었나

### 1쪽. 표지
- **제목**: Daily English: 오늘 내가 쓴 말이 내 단어장이 되는 영어 기록 앱
- **넣을 것**: 앱 로고(d.), 캐릭터 말랑이, 이름·학과, 발표일
- **말할 것**: 한 문장 소개만. 기능 나열은 하지 않음

### 2쪽. 출발점: 친구의 학습 노트 웹앱
- **제목**: 친구의 학습 노트 웹앱을 이어받았다
- **넣을 것**: 원본 홈 화면 캡처(번호 카드 4개), 원본 구성 요약(단어장·표현·대화·일기, 단어 퀴즈, 이메일 로그인, 웹 전용)
- **말할 것**: 콘셉트와 기록 4가지, 노트 디자인 틀은 친구 것을 그대로 이어받았다. 부족했던 점 두 가지: 모으기만 하고 다시 보지 않는 기록, 첫날 할 것이 없는 앱
- **근거**: `docs/contribution.md` 1장

### 3쪽. 다른 앱과 무엇이 다른가 (핵심 가치)
- **제목**: 회사가 만든 교재가 아니라, 내가 겪은 말을 배운다
- **넣을 것**: 비교표

| | 말해보카·스픽 | Quizlet·VoCat | Day One·하루콩 | 메모 앱 | Daily English |
| --- | --- | --- | --- | --- | --- |
| 무엇을 배우나 | 회사가 만든 커리큘럼 | 내가 만든 카드 | 언어 학습 없음 | 아무거나 | 내가 겪은 단어·표현·대화·일기 |
| 다시 보기(복습) | O | O | X | X | O (간격 반복) |
| 일기·감정 기록 | X | X | O | △ | O (+AI 교정) |
| 첫날 볼 것 | 많음 | 공유 세트 | 없음 | 없음 | 꾸러미 1,000개 |
| 월 가격 | 16,000~29,000원 | 4,900~9,900원 | 2,500~12,000원 | 무료 | 핵심 무료, Pro 4,900원 |

- **말할 것**: 단어장 앱은 이미 많다. 우리는 "내 하루의 말"을 모아 두고 잊지 않게 다시 보여 주는 데 집중한다
- **근거**: 가격은 `analysis/pricing/README.md` 2장

### 4쪽. 조사 질문
- **제목**: 기능도, 콘텐츠도, 가격도 감이 아니라 데이터로 정했다
- **넣을 것**: 질문 4개를 번호로
  1. 비슷한 앱 사용자는 무엇에 만족하고 무엇에 실망하나? (리뷰 분석)
  2. 원어민이 쓰는 영어는 우리가 배우는 영어와 얼마나 다른가? (말뭉치 분석)
  3. 넣은 단어·문장이 우리 앱다운가? (콘텐츠 점검)
  4. 얼마를, 어떤 방식으로 받아야 하나? (가격 분석)
- **말할 것**: 각 질문이 앱의 어떤 결정으로 이어졌는지 뒤에서 하나씩 보여 준다

## 2부. 어떻게 조사했나, 무엇을 알아냈나

### 5쪽. 리뷰 데이터와 방법
- **제목**: 비슷한 앱 11개의 리뷰 5,142건을 읽었다
- **넣을 것**: 앱 4묶음(학습: 듀오링고·스픽·말해보카·케이크 / 단어장: Quizlet·VoCat·AnkiMobile / 대화: 헬로톡·탄뎀 / 일기: Day One·하루콩), 수집 출처(Apple 공개 API·RSS), 방법 3단계(주제 14개 키워드 → 낮은 별점 1,310건 vs 높은 별점 3,425건 비교 → 95% 신뢰구간이 0을 포함하면 결론에서 뺌)
- **말할 것**: 작성자 이름은 모으지 않았다. 3점은 만족·불만이 불분명해 뺐다
- **근거**: `analysis/README.md`

### 6쪽. 정확도 점검
- **제목**: 키워드가 엉뚱한 리뷰를 잡지 않는지 직접 읽고 고쳤다
- **넣을 것**: 고친 예 3개("안 돼"가 "기초가 안돼있는데"를 잡음, "고쳐"가 버그 리뷰를 잡음, "fun"이 "function"을 잡음)
- **말할 것**: 숫자를 믿기 전에 표본을 읽었다

### 7쪽. 결과: 별점을 가르는 주제
- **제목**: 사람들은 가격과 오류에 실망하고, 재미·디자인·복습에 만족했다
- **넣을 것**: 막대그래프(낮은 별점 vs 높은 별점 언급률): 가격·구독 31.8% vs 14.2%, 오류 18.4% vs 6.2%, 재미·꾸준함 2.4% vs 15.2%, 디자인 3.1% vs 11.7%, 복습 4.8% vs 9.8%, 나만의 단어장 0.6% vs 4.9%
- **근거**: `analysis/output/themes_overall.csv`

### 8쪽. 결과: 앱 종류별, 느낌
- **제목**: 일기 앱은 데이터 유실, 모든 앱은 "귀엽고 따뜻한 느낌"이 갈랐다
- **넣을 것**: 일기 앱 낮은 별점의 29.0%가 데이터 유실 / 귀여움·감성 높은 별점 6.3% vs 낮은 별점 0.2%
- **근거**: `analysis/README.md` 2장, `analysis/output/ux_overall.csv`

### 9쪽. 그래서 만든 기능
- **제목**: 데이터가 가리킨 곳에 기능을 만들었다
- **넣을 것**: 표 (데이터 → 결정 → 앱 화면)
  - 복습·나만의 단어장이 만족 요인 → 내가 모은 말로 간격 반복 복습
  - 일기 앱의 데이터 유실 → 삭제 되돌리기, 백업, 연결이 끊겨도 저장
  - 꾸준함은 만족, 압박은 불만 → 벌칙 없는 요일 도장
  - 귀여움·감성이 만족 요인 → 노트 디자인 유지, 캐릭터, 따뜻한 색
  - 가격이 가장 큰 불만 → 기록·복습은 계속 무료, 운영비 0원
  - 대화 앱의 사람 문제 → 모르는 사람과 연결하지 않음
- **넣을 것(그림)**: 복습 화면, 백업 화면 캡처 각 1장

### 10쪽. 원어민 영어 vs 교과서 영어
- **제목**: 어려운 건 단어가 아니라 쉬운 단어의 조합이었다
- **넣을 것**: 큰 숫자 96.6%(많이 쓰인 상위 500개 표현 중 교육과정 기본 어휘로만 된 비율), 비교표(I'm fine, thank you 4문장 vs pretty good 852문장 / goodbye 655 vs see you 2,348 / how are you 453 vs what's up 109)
- **말할 것**: 교과서 표현이 더 많이 쓰인 경우도 있다. 정답은 "다 바꾸기"가 아니라 "둘 다 알기"
- **근거**: `analysis/native/README.md`

### 11쪽. 첫날 볼 것: 표현 400개, 단어 600개
- **제목**: 1만 7천 개 후보에서 표현 400개를, 교육과정에서 단어 600개를 골랐다
- **넣을 것**: 깔때기 그림(16,973 → 8,355 → 736 → 400), 단어 600(초급 300·중급 300), 예문 456개는 공개 한영 문장(번호로 출처 표시)·144개는 직접 씀, 표현 꾸러미·단어 꾸러미 화면 캡처
- **말할 것**: 상업적으로 쓸 수 있는 데이터만 썼다(DailyDialog 같은 비상업 데이터는 뺐다)
- **근거**: `analysis/native/README.md`

### 12쪽. 우리 앱다운 콘텐츠인가
- **제목**: 자주 쓰는 말과 우리 앱에 맞는 말은 달랐다
- **넣을 것**: 전후 비교 4줄 (단어 예문 중 "나"의 말 45% → 76%, 존댓말 해석 19% → 4.5%, 어두운 단어 14개 → 0개, 기분 낱말 22 → 32개), 처음 버전의 예(kill, gun, war가 들어가고 sad, angry, hungry가 빠짐)
- **말할 것**: 원인 중 하나는 내 수집 코드의 실수(교육과정 목록의 괄호 속 파생어를 읽지 않음)였다. 실수를 찾아 고친 과정 자체가 이 분석의 결과
- **근거**: `analysis/REPORT.md` 4장

### 13쪽. 가격: 얼마보다 어떻게
- **제목**: 사람들은 "비싸서"보다 "모르게 결제돼서" 화가 났다
- **넣을 것**: 가격 리뷰 991건 중 비싸다 4.4%(낮은·높은 별점 차이 없음) vs 환불 29.1%·해지 12.8%·자동 결제 12.1%(모두 낮은 별점에서 많음), 리뷰에 적힌 금액 중앙값 60,000원(체험 뒤 빠져나간 연간 결제), 서울시 조사(무료 체험 뒤 자동 결제 안내 부족 49%, 해지 어려움 58.4%)
- **근거**: `analysis/pricing/README.md` 1장

### 14쪽. 그래서 정한 가격
- **제목**: 월 4,900원, 한 달씩만, 체험이 끝나도 저절로 결제하지 않는다
- **넣을 것**: 비슷한 앱 월 가격 막대그래프(하루콩 2,500 / VoCat 4,900 / Quizlet 9,900 / Day One 12,000 / 케이크 16,000 / 헬로톡 16,900 / 말해보카 19,500 / 탄뎀 21,500 / 스픽 29,000, 우리 4,900 표시), 결정 3가지, Pro 화면 캡처
- **말할 것**: 처음엔 5,900원이었는데 근거가 없었다. 가장 비슷한 단어장 앱 VoCat의 기본 요금과 같은 4,900원으로, 기록·단어장 앱 중앙값(7,400원)보다 낮다. 3,900원도 검토했지만 앱 안 AI 교정 비용을 감당하려고 4,900원을 골랐다. 대신 연간 결제와 자동 전환을 없애 매출보다 신뢰를 먼저 골랐다
- **근거**: `analysis/pricing/README.md` 2장·결정

## 3부. 무엇을 만들었나

### 15쪽. 앱 화면
- **제목**: 친구 기획의 노트 틀 위에 만들었다
- **넣을 것**: 휴대폰 화면 캡처 4~5장(홈, 단어 꾸러미, 일기와 AI 교정, 복습, 다크 모드)
- **말할 것**: 화면마다 앞의 어떤 데이터에서 나왔는지 한마디씩

### 16쪽. 만든 방법과 품질
- **제목**: 웹과 안드로이드 앱을 같은 코드로, 테스트로 지켰다
- **넣을 것**: React + Vite + Supabase + Capacitor, 단위 테스트 105개·브라우저 테스트 110번(55개 × 데스크톱·모바일, 접근성 검사 포함)·안드로이드 실기 시나리오 7개, 저장소에 올리면 자동 검사, 오류 추적과 신고·관리자 페이지, 릴리즈 APK 1.31MB, 운영비 월 0원
- **근거**: `README.md`, `docs/project-overview.md` 5장

### 17쪽. 누가 무엇을 했나 (AI 사용 공개)
- **제목**: 친구의 기획, 나의 결정, AI의 손
- **넣을 것**: 세 칸 표
  - 친구: 콘셉트, 기록 4가지, 노트 디자인 틀
  - 나: 방향·질문·기준·디자인 선택·결과 확인
  - AI(Claude Code): 코드, 분석 코드, 콘텐츠 초안
- **말할 것(그대로 읽어도 됨)**: "코드와 콘텐츠 초안은 AI 코딩 도구와 함께 만들었고, 무엇을 만들지, 어떤 기준으로 고를지, 결과를 받아들일지는 제가 정했습니다. AI가 쓴 예문은 무작위 표본을 사람이 다시 읽어 확인했습니다."
- **근거**: `docs/contribution.md` 2~3장
- **발표 전 할 일**: `analysis/native/output/human_review_sheet.csv` 50개를 나와 친구 한 명이 따로 표시하고 일치율을 이 쪽에 적기(예: "두 사람이 50개 중 47개에서 같은 판단")

## 4부. 한계와 다음 단계

### 18쪽. 한계
- **제목**: 이 분석으로 말할 수 있는 것과 없는 것
- **넣을 것**
  - 실제 사용자 데이터가 없다: 아직 공식 출시·발표 전이라 사용자를 모으지 않았다(발표 전 결과물 공개, 개인정보 처리방침·운영 준비 미완료). 그래서 공개 리뷰와 공개 말뭉치로 근거를 대신했다
  - 리뷰와 별점의 관계는 상관이지 인과가 아니다
  - 한국 App Store만 봤다
  - 콘텐츠 선정과 가격에는 사람(과 AI)의 판단이 들어갔다. 원어민 검토와 지불 의향 설문이 필요하다
- **근거**: `analysis/REPORT.md` 7장, `analysis/pricing/README.md` 한계

### 19쪽. 다음 단계와 정리
