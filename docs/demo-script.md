# 학술제 시연 진행표

휴대폰 두 대로 "친구와 주고받은 말이 내 공부가 되는 하루"를 4분 안에 보여 준다.

- **휴대폰 A (나, 학습자)**: 시연 계정 `내주소+demo@gmail.com`. 3주 동안 쓴 것처럼 기록을 미리 채운다.
- **휴대폰 B (외국인 친구 역할)**: 시연 계정 `내주소+demofriend@gmail.com`. 친구 이름은 지어낸 이름(예: Sunny)으로 쓴다.
- 화면은 A를 프로젝터에 미러링한다. B는 발표자 옆 사람이 들고 문장을 보낸다.

> 발표 첫마디에 꼭 말한다: **"시연용 계정이고, 3주 동안 쓴 것처럼 미리 넣은 예시 데이터예요. 실제 사용 수치는 뒤에서 따로 보여 드릴게요."**
> 시연 계정(+demo)은 사용 기록 분석에서 자동으로 빠진다(analysis/usage).

## 전날 준비 (30분)

1. **계정 두 개 만들기** (직접): 웹에서 `+demo`, `+demofriend` 이메일로 가입하고 확인 메일의 링크를 누른다. Gmail은 `+` 뒤가 달라도 같은 메일함으로 온다.
2. **친구로 짝 맺기**: B에서 친구 탭 > 추가 > "친구"로 초대 번호 만들기 → A에서 그 번호로 들어가기. 닉네임은 A "나", B "Sunny"처럼.
3. **시연 데이터 만들기**: 발표 **전날** 실행한다(오늘 날짜를 기준으로 21일 전까지 채우고, 오늘은 비워 둔다).
   ```powershell
   node scripts/make-demo-data.mjs --end 발표날짜(예: 2026-12-03)
   ```
   - `demo-data/demo-backup.json` → A에서 **설정 > 데이터 > 파일에서 가져오기** (단어 14, 표현 14, 문법 4, 일기 12, 대화 4)
   - `demo-data/demo-sentences.sql` → Supabase **SQL Editor**에 붙여 넣고 Run (지난 10일치 친구 문장 20개와 반응)
4. **리허설 한 번** (아래 순서 그대로). 리허설에서 보낸 오늘 문장은 아래 "다시 하기"로 지운다.
5. **꼭 확인할 것** (아직 실제로 확인한 적 없음)
   - AI 교정이 실제로 되는지(서울 서버에 Gemini 키). 안 되면 4번 장면은 "이미 받은 교정"으로 바꾼다.
   - 친구 문장이 새로고침 없이 바로 뜨는지(실시간). 안 되면 친구 탭을 한 번 눌러 새로 불러온다(5초마다 다시 불러오는 장치도 있음).
6. 휴대폰 두 대 충전, 글자 크기 기본, 방해 금지 모드, 학교 와이파이가 막힐 때를 대비해 휴대폰 핫스팟 준비.

## 막혔을 때

| 상황 | 대신 할 것 |
| --- | --- |
| AI 교정이 15초 넘게 안 옴 / 오류 | 달력에서 기준일 4일 전 일기("미국에 사는 친구가…") 열기: "이미 받은 교정을 보여 드릴게요" (a nice place **to live** 교정이 들어 있음) |
| 친구 문장이 바로 안 뜸 | A에서 친구 탭을 다시 누르기. 그래도 안 되면 "어제 받은 문장"으로 설명 |
| 와이파이 끊김 | 핫스팟. 기록은 끊겨도 저장되고 다시 연결되면 올라간다는 점을 오히려 보여 준다 |
| 오늘 문장을 이미 보냄(하루 한 문장) | 아래 "다시 하기" SQL로 오늘 문장을 지운다 |

## 다시 하기 (리허설 뒤)

오늘의 문장은 하루에 한 사람당 하나라서, 리허설에서 보냈으면 지워야 본 발표에서 다시 보낼 수 있다. SQL Editor에서:

```sql
delete from public.couple_sentences s
using auth.users u
where u.id = s.user_id
  and u.email like '%+demo%'
  and s.day = (now() at time zone 'Asia/Seoul')::date;
```

AI 교정은 한 사람당 하루 5번까지라, 발표 당일 리허설에서는 1번 이하로만 쓴다.
