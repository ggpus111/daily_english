# 누가 무엇을 했나: 친구 원본, 내가 한 일, AI 사용

발표에서 "친구가 만든 것과 내가 한 것은 어디까지인가요?", "AI를 썼나요?"라는 질문에 답하려고 정리한 문서입니다.

## 1. 친구가 보내 준 원본

친구가 보내 준 자료는 웹앱 소스 코드 한 묶음(`daily-english-main.zip`)이었습니다.

| 항목 | 원본 |
| --- | --- |
| 형태 | 웹앱(PWA), React + Vite, 화면 코드 대부분이 `App.jsx` 한 파일(686줄) |
| 콘셉트 | "작은 기록이 모여 나만의 언어가 돼요" / "Little notes become your own language." |
| 기록 4가지 | 단어장(단어·뜻·예문), 표현 모음(표현·뜻, 검색), 대화 기록(상황·메시지·뜻·설명, 카테고리 7개), 오늘의 일기(모국어로 쓰고 직접 번역, 메모) |
| 복습 | 단어 퀴즈(영어 → 뜻, 뜻 → 영어), 점수 |
| 홈 | 학습 노트 디자인: 인사말, 번호 카드 4개(01 VOCABULARY ~ 04 DAILY JOURNAL), 파스텔 카드 |
| 로그인·저장 | 이메일 로그인(Supabase), 기록은 기기 저장 후 서버 표 하나(`learning_records`)에 동기화 |
| 설정 | 학습 언어·모국어 선택, 로그아웃 |
| 테스트·문서 | 없음(README는 Vite 기본 문서) |

원본에서 그대로 이어받은 것: **콘셉트 문장, 기록 4가지의 구성, 홈의 노트 디자인 틀(번호 카드 4개, 파스텔 카드, "d." 로고 자리)**. 이후 디자인을 바꿀 때도 "친구 기획의 틀을 유지한다"를 원칙으로 삼았습니다.

## 3. AI 사용 공개

이 프로젝트는 **AI 코딩 도구(Anthropic의 Claude, Claude Code)**를 써서 만들었습니다. 숨기지 않고 역할을 나눠 밝힙니다.

| 일 | 사람(나) | AI |
| --- | --- | --- |
| 방향과 목표 | 무엇을 만들지, 무엇이 중요한지 정함(친구 기획 유지, 월 운영비 0원, 데이터로 결정, 앱의 느낌이 가장 중요) | |
| 질문 만들기 | 분석할 질문을 정함("외국인이 쓰는 영어와 우리 영어는 얼마나 다를까", "단어 500개 이상은 있어야 하지 않나") | 질문을 측정 가능한 방법으로 바꾸는 안을 냄 |
| 디자인 결정 | 시안 중 고르고 고칠 점을 지적(색이 안 어울림, 다크 모드 글자가 안 보임, 원본과 너무 다름) | 시안과 코드 작성 |
| 코드 | 요구 사항과 확인 | 대부분의 코드와 테스트 작성 |
| 데이터 수집·분석 | 데이터 사용 원칙(상업 이용 가능, 개인정보 수집 안 함)과 결과 해석·결정 | 수집·분석 코드 작성, 표본 점검, 수치 정리 |
| 콘텐츠 | 개수와 기준을 정함(단어 600, 표현 400, 우리 앱다운 말) | 단어 뜻, 표현 예문, 직접 쓴 예문 초안 작성 |
| 문서·발표 | 발표 구성과 PPT 제작 | 분석 문서 초안 |

**AI를 썼다는 것이 3번 지적(고르는 사람이 혼자였다)을 해결하지는 않습니다.** 오히려 "AI와 한 사람"이 만든 콘텐츠라는 점이 드러납니다. 그래서 공개와 함께 아래 검증을 보탭니다.

- **사람 검토 표**: 단어 예문 50개를 무작위로 뽑은 표(`analysis/native/output/human_review_sheet.csv`)를 만들어 두었습니다. 나와 친구 한 명이 따로 읽고 "뜻이 맞나 / 번역이 맞나 / 우리 앱 말투인가"를 표시하면, 두 사람의 일치율로 콘텐츠를 사람이 확인했다고 말할 수 있습니다.
- **AI가 쓴 콘텐츠 표시**: 단어 예문 중 Tatoeba 문장(456개)은 앱에 문장 번호를 표시하고, 번호가 없는 144개는 직접(AI와 함께) 쓴 문장입니다.
- **발표에서 말할 문장**: "코드와 콘텐츠 초안은 AI 코딩 도구와 함께 만들었고, 무엇을 만들지, 어떤 기준으로 고를지, 결과를 받아들일지는 제가 정했습니다. AI가 쓴 예문은 무작위 표본을 사람이 다시 읽어 확인했습니다."

## 4. 실제 사용자가 아직 없는 이유

이 앱은 아직 공식적으로 출시하거나 발표한 적이 없습니다. 학술제 발표 전에 앱스토어에 올리거나 사용자를 모으면, 발표 전에 결과물을 공개하는 셈이고, 개인정보 처리방침과 운영 준비(문의 대응, 서버 관리)도 끝나지 않은 상태였습니다. 그래서 이번 분석은 **비슷한 앱의 공개 리뷰와 공개 말뭉치**로 근거를 대신했고, 실제 사용자 검증은 발표 뒤 베타 테스트로 미뤘습니다(무엇을 잴지는 [../analysis/REPORT.md](../analysis/REPORT.md) 7장).
