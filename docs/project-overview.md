## 1. 왜 만들었나

친구가 만든 학습 노트 웹앱(`App.jsx` 한 파일, 686줄)을 이어받았습니다. 원본에서 그대로 가져온 것은 **콘셉트 문장, 기록 4가지 구성, 홈의 노트 디자인 틀(번호 카드 4개, 파스텔 카드, "d." 로고)**입니다.

원본에서 부족했던 두 가지
1. **모으기만 하고 끝나는 기록**: 다시 볼 때를 알려 주는 복습이 없고, 일기 교정은 혼자 해야 했습니다.
2. **첫날 할 것이 없는 앱**: 기록이 없는 사람은 볼 것이 없었습니다.

다른 앱과의 차이: 말해보카·스픽은 회사가 만든 교재를, 메모 앱은 기록만, 일기 앱은 언어 학습이 없습니다. Daily English는 **내가 겪은 말**을 모으고, 잃어버리지 않게 지키고, 잊을 때쯤 다시 보여 줍니다.

원칙(처음부터 끝까지 지킨 것)
- 친구 기획의 노트 틀은 유지하고, 시중 앱 수준으로만 다듬는다
- 월 운영비 0원
- 기능·콘텐츠·가격은 감이 아니라 데이터로 정한다
- 앱의 느낌(따뜻한 나의 기록)이 가장 중요하다

### 알림 규칙

- 하루 목표를 못 채웠으면 **13시**에 처음, 그 뒤 **1시간 30분~2시간 30분**마다(21시까지, 하루 최대 5번). 목표를 채우면 그날 남은 알림은 빠집니다.
- 복습할 것이 있는 날만 복습 알림.
- 안드로이드는 3일 치를 미리 예약(휴대폰을 껐다 켜도 유지), 웹은 탭이 열려 있을 때만 옵니다.
- 기본은 꺼짐. 리뷰 분석에서 압박·죄책감이 불만 요인이라 문구를 다그치지 않게 썼습니다.

### 분석 1. 사용자 리뷰 (5,142건)

방법: 앱 4묶음(학습 / 단어장 / 대화 / 일기) → 주제 14개를 키워드로 찾기 → 낮은 별점(1~2점, 1,310건)과 높은 별점(4~5점, 3,425건)의 언급률 비교 → 차이의 95% 신뢰구간이 0을 포함하면 결론에서 뺌. 3점은 뺐고, 작성자 이름은 모으지 않았습니다. 키워드가 엉뚱한 리뷰를 잡는지 표본을 읽고 고쳤습니다("안 돼"가 "기초가 안돼있는데"를, "fun"이 "function"을 잡음).

### 분석 2. 원어민 영어 vs 교과서 영어

- 많이 쓰인 상위 500개 표현 중 **96.6%**가 교육과정 기본 어휘로만 되어 있음 → 어려운 건 낯선 단어가 아니라 **쉬운 단어의 조합**(hang out, figure out)

### 오류 추적과 신고

- 처리 못 한 오류(화면 오류, Promise 거부, window error)를 이 기기에 최근 30개 모읍니다. 같은 오류는 한 줄로 묶고, 사용자가 쓴 내용은 넣지 않습니다.
- 로그인했으면 서버(`client_errors`)로도 보냅니다. 관리자 페이지에서 같은 메시지끼리 묶어 횟수와 마지막 시각을 봅니다.
- 사용자는 프로필에서 문제를 신고(앱 오류 / 단어·표현 내용 / 의견)하고, 처리 상태와 답변을 봅니다. 관리자는 상태와 답변을 바로 고칩니다.
- 안드로이드 네이티브 크래시는 Play 스토어 출시 뒤 Play Console(Android vitals)에서 봅니다.

## 6. 보안과 개인정보

- 데이터는 행 단위 보안(RLS)으로 본인 것만 읽고 씁니다. 관리자 권한도 서버 함수(`is_admin()`)로만 확인합니다.
- 앱에는 공개용 anon key만 들어가고, service_role 키는 어디에도 넣지 않습니다.
- 암호화하지 않은 http 통신 차단, 앱 저장소의 클라우드 백업 끔(로그인 토큰 보호), 공유 창에는 캐시 폴더만 엶.
- 웹 보안 헤더(CSP 등)를 `vercel.json`에 넣고 브라우저 테스트로 확인.
- 리뷰 작성자 이름은 모으지 않았고, 오류 기록에는 사용자가 쓴 내용을 넣지 않습니다.
- 개인정보 처리방침 화면에 기록, 오류, 신고를 무엇을 왜 모으는지 적었습니다.
- 정확한 알람 권한은 Play 정책 때문에 뺐습니다. 알림 권한은 알림을 켤 때만 묻습니다.
